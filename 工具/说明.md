# 收图验收工具 · 说明

接住 GPT 交回的换装姿势图（睡衣/冬装版），帮人快速逐张验收，再一键装进项目。

## 怎么用

1. **双击项目根目录的「双击收图验收.bat」**。它会：
   - 自动扫描互助文件夹（顶层和「看板娘」项目文件夹下）所有 `GPT_日期[_批次]_成品_看板娘换装姿势` 形状的交付目录，把里面的新图复制到项目的「收图」文件夹（检查记录、预览、未采用稿这些不在 角色\衣服 结构里的不会收）；
   - 也可以自己把图放进「收图」文件夹，结构照旧：`收图\角色名\pajamas 或 winter\文件名.png`（文件名和底图同名）；
   - 打开浏览器里的验收页。
2. **在验收页逐张看**。每张卡片自动体检四样：
   | 检查 | 什么意思 |
   |---|---|
   | 尺寸 | 应该和底图一样是 1024×1536 |
   | 白底干净 | 四边不该有阴影、地面、水印 |
   | 脸和底图一致 | 只换衣服的图，脸不应该大变（会拿"身上的改动量"做对照） |
   | 位置大小贴合 | 去掉背景后人物轮廓框应和底图基本重合 |
   还有三种看法：**新收的图**、**叠加对比**（拖滑块，或点一下图让它闪烁）、**轮廓叠影**（品红=底图，青=新图，重合成深色）。姿势、道具、衣服细节还是要人眼确认。
   判断完点 **通过 / 退回 / 待定**，页面上方能一键"没问题的都标通过"（只标自动体检全绿的）。
3. **下载「验收结果.json」**，回到黑窗口运行：
   ```
   node 工具\收图验收.mjs 装入 验收结果.json
   ```
   它只装「通过」的图：拷到 `models\角色名\衣服\`，并自动重写角色包 `character.js` 里的 `outfitPoses`（以 models 里的文件为准，改前有备份）。装完重新打开桌面宠物/网页才生效。

## 判定和图片版本是绑定的

- 判定按「路径 + 内容哈希」记忆：同一张图换过稿（内容变了），旧的通过/退回自动失效，回到待定，必须重新验收。
- 「验收结果.json」里带每张图的哈希；装入时会重新算一遍核对——结果文件是旧的、或图又换过了，都会拒绝装入。
- 不同交付目录里同名但内容不同的图会标「冲突待选」：不能判定、不进导出、装入也会拒绝。各来源都保留不动；把选中的那张复制进 `收图\角色\衣服\` 覆盖，再跑一次本工具，就会标「已选稿」并恢复正常验收。

## 注意

- 走路图（walk1/walk2）目前停用：登记了也不会显示，等以后重新启用走路。
- 「装入」改的是**所在项目**的文件；在哪个文件夹运行就装进哪个项目。
- 退回的图不装；GPT 重画后再放进「收图」重新验收就行（已装入的图会标"已装入项目"）。
- 自动体检只是助手，不能替人做最终判断——以前出过"整张重画、身体对不上"的图，轮廓叠影一眼就能看出来。

# 角色包校验 · 说明

改完角色包（characters/*/character.js）或加了新角色后，跑一遍体检：

```
node 工具\角色包校验.mjs
```

- 逐个角色输出 PASS / FAIL，FAIL 会列出具体缺什么；有 FAIL 时退出码是 1，可以接在脚本里当门禁。
- 检查内容：必填字段存在且类型对（立绘角色查 images.normal、outfits、faceBox、scale、sitSeat、sitSway、sway 等；Live2D 角色查 model、motions、mouthParam 等）；模型和图片路径指向的文件真实存在；台词是字符串或数组（按时段/等级再分一层的也认）；touchZones、moods、states 结构完整。
- 语音（voice）只做提示不判失败——没配音色的角色不会说话，但不算坏包。
- 人物名单（characters/index.js）和文件夹会对两边：名单里有没建文件夹的、或文件夹没登记进名单的，都会报。
